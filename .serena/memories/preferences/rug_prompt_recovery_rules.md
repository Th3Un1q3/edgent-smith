Decision (2026-10-21, supersedes the per-example try/catch rule): .opencode/agents/rug.md expresses failure handling ONCE, in a single execution envelope, and every example is an orchestration body for it. Envelope: const trace = []; try { trace.push('<progress>'); <orchestration>; return { trace, result } } catch (e) { throw JSON.stringify({ trace, audit: await tools.subtask_ls({ count: 10 }), error: String(e) }) } — the audit is captured on failure so the next execution can see which children existed and recover them, and the trace always travels. One shared run(args) helper: success requires status ok, not truncated, non-empty outputText; a FRESH call resumes at most once when the result carries a task_id, with interruption wording; a call that is already a resume never resumes; an empty resume returns the first result and preserves its status. Resume must pass an explicit field list and MUST NOT carry fork_from — fork_from and task_id are mutually exclusive and the runner throws. Bodies contain no try/catch, no helper definition, no function w, and use trace.push for progress. Retrospective is a stage, not a hook: the orchestrator interrogates every returned child including silent ones, aggregates reports by id, hands the bundle alone to one fresh harness-management subtask that does not interview, then writes and re-reads memory. Cross-execution chaining: subtask_tail(task_id, count 3), normalise string-vs-array, take the last non-empty outputText in the same code, feed a fresh child. Lesson: one owner per rule — duplicating a wrapper across examples creates contradictory guarantees; and qualified absolutes ('second in-block resume') are needed where a separate stage legitimately resumes.
