# ADR-015: Generic skill-tunable worker agent replaces the software-engineering-bound rug-swe identity

## Decision

`rug-swe` is reworked into one task-agnostic worker agent that executes any task type, with specialization arriving only through skills. The resident prompt holds no profession and no domain method, and is capped at five behavioral statements: state a task contract before work (task, scope, acceptance criteria, evidence bar); load the named packs into a declared skill slot, prefer the smallest matching pack, and fall back to a general-delivery pack that ships with the worker so a task with no domain pack still has acceptance criteria and a proof-of-done artifact; classify the task, set phases and reserve roughly a tenth of the budget for verification; close with a report contract (outcome, evidence, residual risk, spend); and claim completion only on a checkable artifact. The pack contract has five fields — domain acceptance criteria, domain anti-patterns with hard-negative examples, a checkable proof-of-done artifact, the gap-interrogation policy, and domain reference material — so gap interrogation arrives as a contract field rather than as resident prose, and the general-delivery pack is a fully specified pack rather than a placeholder. Delimiter and format conventions are supplied by the pack and harness, not the resident prompt. Final shape as implemented: one agent id, `rug-swe`, holds the generic worker, and no second id and no alias exist. Specialization arrives only through the three packs that ship — `software-engineering`, `diff-discipline` and `general-delivery` — and the software-specific method and the archetype routing live in the packs, not in the worker: the task-archetype routing table the old software-engineering definition carried now sits in `software-engineering/SKILL.md` under `## Route by task archetype`, 24 rows, with a no-match row that points at `general-delivery`. Software work keeps today's guarantees by loading the `software-engineering` pack, which supplies TDD-first, minimal-diff and test requirements, and `diff-discipline` supplies edit scope; existing `rug-swe` invocations still resolve because the definition was replaced in place rather than aliased.

## Considerations

### Context

`rug-swe` is 179 lines and 14 KB of prose whose identity is a senior software engineer. Its standards are profession-bound ("minimal, correct diffs", "TDD first", "tests are not optional", no debug logging), so every phase inherits a code bias before the task is classified. Its `Task Archetype to Skill Mapping` table routes only to test, refactor, CLI, Docker and Bun skills, and has no default row, so a research, writing or operations task matches nothing and skill selection fails silently rather than erroring. Its workflow assumes a repository: per-file work packages, path verification and a file-path anti-pattern leave non-file deliverables with no representation, and the scaffold and implement phases have no analogue outside code.

The decision is constrained by four findings in `mem:researches/agentic-engineering/prompt-engineering`. First, models saturate after roughly four to five stacked behavioral rules in one layer, and prompt sprawl produces drift and ignored rules — so a generic prompt cannot absorb every domain's method inline; the method must load on demand. Second, prestige persona framing inflates register without improving correctness, so the generic identity must drop the "senior engineer" flattery and keep only operational constraints. Third, verification that works is a pre-commit assertion pass and a context shift, not same-turn self-critique — so proof of done has to be a separate, checkable artifact supplied by the pack, not a resident claim to "be careful". Fourth, delimiter discipline: explicit XML tags create parsing boundaries that Markdown headers cannot, because ingested content carries its own headers and code blocks, so the worker tags its contract, its untrusted input and its skill slot instead of trusting section prose. `mem:researches/agentic-engineering/production-ai-architecture` adds the determinism-first rule: permission boundaries and gates are enforced by deterministic infrastructure — sandboxes, policy checks, harness permission denials — because prompt text is a probabilistic suggestion and cannot be a security boundary. Skills carry the domain checklists and reference material a task loads, never authorization; the resident prompt carries only the obligation to state the boundary and respect it. The same memory's lean-adoption heuristic is what defers a multi-agent farm until domains prove divergent.

The harness composes exactly one prompt file per agent and offers no include mechanism, so a shared core plus per-agent references would collapse into copy-paste. `mem:architecture/adr/ADR-009-skill-usage-heuristics` already establishes skills as the routing layer, and this ADR applies that decision to the worker's own identity.

### Options considered

**A. Keep `rug-swe` as it is.** Pros: no migration; code work keeps its tested defaults; one file to maintain. Cons: non-code tasks route to no skill; the identity biases every phase; the prompt is already over the saturation ceiling, so adding domains is not possible.

**B. One generic worker plus skill packs.** Pros: resident prompt stays small and domain-free; any task type is representable; domain method stays editable without touching the core; a failing domain is fixed in one pack. Cons: skill selection can no longer be enumerated statically, so a default pack and a gap manifest are mandatory; code work degrades when no pack is loaded; packs need their own review gate to stay consistent.

**C. Per-domain agent farm.** Pros: each agent is small and maximally tuned; no routing indirection. Cons: N resident prompts drift on every core edit; the agent count in `AGENTS.md` and `just verify-agents` becomes a maintenance tax; duplicated contract and verification prose; the same sprawl failure at directory scale.

**D. One monolithic generic worker with all domain rules inline.** Pros: no pack system; no routing failure mode. Cons: immediately exceeds the constraint ceiling; every domain rule biases every task; verification becomes a generic "check your work" claim, which the research records as a constraint-shaped void.

### Scoring

Criteria scored -2 to +2, higher is better.

| Criterion | A as-is | B worker + packs | C agent farm | D monolithic |
|---|---|---|---|---|
| Task-type coverage (non-code representable) | -2 | +2 | +2 | +2 |
| Constraint headroom (stays under the saturation ceiling) | -2 | +2 | +1 | -2 |
| Verification integrity outside code | -1 | +1 | +1 | -1 |
| Maintainability and drift | 0 | +2 | -2 | -1 |
| Flexibility to add a domain | -2 | +2 | +1 | +1 |
| Implementation ease on this harness | +2 | +1 | 0 | +1 |
| Initial implementation cost (cheaper is higher) | +2 | 0 | -2 | +1 |
| **Total** | **-3** | **+10** | **+1** | **+1** |

B wins because it is the only option that scores positively on coverage, headroom and verification at the same time: coverage and headroom are in direct tension, and only externalized method resolves it. A sacrifices coverage for nothing. C reaches coverage but pays for it in drift, which is the failure the research attributes to duplicated prompts. D buys coverage by spending the headroom that makes the prompt followable. B's headroom score is earned at five resident statements — the ceiling the corpus names, not above it — and the audit in Consequences records what was moved out to reach that count. No constraint overrides the scores; the alias requirement for existing `rug-swe` callers is satisfied by B's migration step rather than by a separate option.

### Consequences

`.opencode/agents/rug-swe.md` now holds the generalized worker: the software-engineering definition was replaced in place and the frontmatter `name` stays `rug-swe`, so the agent count is unchanged and no alias file exists. `.opencode/agents/rug-worker.md` is absent — the swap deleted it rather than leaving a duplicate to remove — so `rug-swe` is not kept beside a second worker id. `AGENTS.md`'s agent taxonomy and `just verify-agents` were updated in the same change, and the worker passed `just verify-agents` and `just ci-fast` at 13 of 13 gates. Three packs ship under `.agents/skills/` — `software-engineering`, `diff-discipline` and `general-delivery` — and the software-engineering pack carries the 24-row archetype table with its no-match row pointing at general-delivery.

What `rug-swe` users lose: TDD-first, minimal-diff, no-debug-logging, per-file work packages and path discipline are no longer resident, so a bare invocation with no pack loaded is weaker on code than today; that is the intended trade, and it is why the worker's resident core makes loading the pack its first call rather than leaving it to the caller's memory. The archetype table also stops being the routing authority, so an unmatched task now surfaces as a gap manifest instead of silently selecting nothing.

Migration was incremental rather than a flag day. The existing archetype table moved into the `software-engineering` pack first, so the pack started from verified coverage rather than a rewrite; the swap then replaced the definition in place, with no alias period; and the other two packs shipped with the worker rather than waiting for a task to need one, because the pack contract is what makes a task type representable and `diff-discipline` carries scope rules that need no domain. Acceptance was a review rather than a sample: two cold-reader reviews of the worker and a mechanics audit against the old software-engineering definition, followed by `just verify-agents` and `just ci-fast` at 13 of 13 gates.

The worker avoids becoming a lowest-common-denominator prompt by keeping the core at the five statements named in the Decision and nothing else, and by requiring each pack to satisfy the five-field contract stated in the Decision — acceptance criteria, anti-patterns with hard-negative examples, a checkable proof-of-done artifact, a gap-interrogation policy, and domain reference material. A pack that restates the core is rejected as adding saturation without capability. When no pack matches and no default applies, the worker emits a gap manifest and stops, so absence of a pack is visible instead of silently downgrading quality.

Core stack audit against the saturation ceiling: the first draft of this ADR listed nine resident rules — four contract elements plus five invariants — and still claimed +2 headroom, which the cited ceiling of roughly four to five stacked behavioral rules contradicts. The core is cut to the five statements in the Decision, each kept because removing it breaks a property this ADR depends on: without a task contract the work is unverifiable, without the slot specialization never loads, without the loop there is no budget to reserve, without the report no accountability survives, and without the evidence rule completion becomes self-assertion. Two of the former invariants are not behavioral rules: residual risk is a field of the report contract, and gap interrogation is a field of the pack contract whose three-question cap is a pack-set policy, not resident prose. Schema fields and defaults are the schema-bound scratchpad and pre-action check the same corpus recommends, so they do not stack on the prose layer the ceiling measures. The citation is kept; the divergence is bounded to that schema-versus-prose distinction and does not dismiss the ceiling.

Delimiter discipline is applied structurally rather than as a sixth rule: the worker prompt wraps the task contract, untrusted input and skill slot in XML-tagged regions while the human-readable sections stay Markdown, so a pasted brief that carries its own headings cannot impersonate instructions.

Open questions. Three questions were open when this ADR was written; the repository answered two of them and they are removed from this list. The worker's id and file name are settled as `rug-swe` at `.opencode/agents/rug-swe.md`, whose frontmatter `name` is `rug-swe`, so there is one id and no second one. The alias half of that question is closed in the negative: `rug-swe` does not survive as an alias, and no mode argument replaced it — its definition was replaced in place and `.opencode/agents/rug-worker.md` was deleted, so nothing is left for an alias to sit beside. Which packs ship is settled as all three: `software-engineering`, `diff-discipline` and `general-delivery`. One question stays open: the exact task sample and sign-off used as the no-regression bar. It stays open because no non-software sample has been run — two cold-reader reviews, a mechanics audit against the old definition, `just verify-agents` and `just ci-fast` at 13 of 13 prove the worker's structure, wiring and gates, and none of them measures whether a non-code task now reaches the standard code work did. Until that sample exists, what this ADR supports is that non-code work is representable, not that it is as good.
