# ADR-006: Portable agentic coding setup (agent-devkit)

## Decision
Adopt agent-devkit: a public, MIT-licensed repository delivering a portable OpenCode setup as Dev Container Features on stock base images, consumed through a per-project devcontainer.json generated by a scaffolder CLI. Skills are baked into each container at build time, fetched from the public edgent-smith repository at pinned refs and filtered per project; MCP is served by a Docker MCP Gateway sidecar with a sanitized catalog; all versions are pinned and updated by automation.

## Considerations

### Context
- Personal-first setup, shareable later; public GitHub repo, MIT; GHCR hosts artifacts.
- Must work across machines and projects; OpenCode is the only target harness; Docker and Dev Container hosts only.
- Contents extracted from edgent-smith: skills, harness config (including rug* agents), MCP wiring. Deferred with seams: project instructions/commands, toolchain provisioning, secrets tooling, templates, memory.
- Prior research favored a prebuilt harness image; this decision revises that toward stock-base composition.

### Options considered
#### Option A: Prebuilt OCI harness image + spec + Features
Pros: pinned baseline; fast container start; known-good image.
Cons: image rebuild for any baseline change; extra CI pipeline; Features cannot installsAfter baked Features.
#### Option B: Spec + Features on stock base images  [chosen]
Pros: no image pipeline; stock-base updates free; maximum per-project composition; one artifact type.
Cons: build-time network pull of skills; slower start than a prebuilt image.
#### Option C: Prebuilt image only
Pros: single pinned artifact; simplest per-project file.
Cons: no per-project composition; every tweak means rebuild and republish.
#### Option D: Host bootstrap script (no container)
Pros: trivial to write; no Docker dependency.
Cons: machine drift; no cross-machine reproducibility.

### Scoring
Criteria (-2..+2; for cost, +2 = lowest cost): Maintainability; Flexibility; Implementation ease; Initial implementation cost.
| Criteria | A | B | C | D |
|---|---|---|---|---|
| Maintainability | 1 | 2 | 1 | -2 |
| Flexibility | 1 | 2 | -1 | -2 |
| Implementation ease | -1 | 1 | 0 | 2 |
| Initial implementation cost | -1 | 1 | -1 | 2 |
| Total | 0 | 6 | -1 | 0 |

Highest total: Option B. No override.

### Consequences
- agent-devkit publishes one Dev Container Feature (with options) to GHCR; the harness layer - pinned OpenCode, loader, selected skills, MCP client bits, rug* agents - installs at container build on a stock base.
- Skills bake to ~/.config/opencode/skills/<name>/SKILL.md; install-time filter via Feature option (default: all). edgent-smith's skills-loader reads project .agents/skills only and must be repointed to the global path so subagents see baked skills.
- Prerequisite: sanitize edgent-smith skills upstream to path-agnostic content (canonical workspace conventions, env vars for host endpoints) - removes ~103 absolute refs across 23 files; the direct pull keeps working.
- Source pinning: edgent-smith is public (HTTPS clone, no auth); bake at a pinned commit; feature and tag refs pinned per project; bot bumps.
- MCP: gateway sidecar via the project's compose devcontainer; sanitized catalog shipped by agent-devkit; per-project enable and override; credentials machine-local, referenced by env-var name only.
- Scaffolder: devkit init emits devcontainer.json, compose, and config stubs with option flags (skills selection, MCP servers, versions).
- Licensing: edgent-smith gains an MIT LICENSE file upstream (build-plan prerequisite) since agent-devkit bakes its content into a public artifact.
- Deferred with seams and known gaps: project instructions/commands; toolchain provisioning; secrets tooling; templates; memory; no SKILL.md linter; OpenCode permission.ask gap; OTel naming instability; compose feature-publish caveat (cli #900) to validate at build time; base images must be Feature-capable (Debian/Ubuntu devcontainer bases).
