# One ambiguous answer cost one round

## Failure Modes

- **Symptom.** The rework request "remove the contract, it's confusing" admitted two readings — drop the section that documents the contract, or drop the contract concept itself — and the orchestrator executed one reading; the user met the disambiguating question only in the next round.
- **False hypothesis.** That the answer was unambiguous enough to act on, so the ask needed no branch for a second reading.
- **Root cause.** The ask that produced the answer offered one reading and no branch for a second: it presented the rework as a single choice, so nothing in the question forced the user to name which sense of "contract" they meant, and the ambiguity surfaced a round after the spend.
- **How confirmed.** The orchestrator asked again instead of guessing; the second answer named the sense the first had left open, and both readings had survived the first pass.
- **Prevention.** The dispatch author writes the ask so every reading is a labelled option — "drop the section", "drop the concept" — and sends it before any child acts on the answer; an answer a second reader could parse two ways goes back as options rather than into a dispatch.
