# Server Addition — Decision-Tree Impact & Checklist

Adding an MCP server to the gateway catalog (mcp/catalog.yaml) that can serve a context-gathering need requires updating the context-gathering decision tree: references/server-selection.md (capability matrix, category heuristics, escalation chain) and references/content-fetch-api.md (tool table, error shapes) in the context-gathering skill; a new capability family also gets a routing row in its SKILL.md. Canonical procedure: .agents/skills/docker-mcp-gateway/workflows/catalog.md (Decision-Tree Impact section). (Source: operator requirement; embedded in the docker-mcp-gateway skill files.)

Checklist when adding a server: (1) catalog form — flat `type: server` + image/command/volumes/env/disableNetwork for containers, `type: remote` + remote:{url, transport_type, headers} for remote; verify against the live build (skill may show older nested forms); (2) header nesting — headers go inside the remote block; use ${VAR} and secrets block; (3) enablement — container servers spawn only after mcp-add (pulls image) or --enable-all-servers; (4) digest pinning — pin image@sha256:...; mutable tags violate security controls; (5) --block-secrets is value-heuristic; disableNetwork: true is the egress cut-off; (6) catalog is not hot-reloaded — restart gateway, then verify with gateway_mcp-find; (7) host-side diagnostics via docker compose exec mcp_gateway on the host; (8) volume sources resolve against the gateway dind namespace; (9) remote servers need explicit transport_type; host processes connect as type: remote via host.docker.internal; (10) recipes declare minimal sandbox server sets — adding a server later costs re-activation; (11) decision-tree impact check (this rule).
