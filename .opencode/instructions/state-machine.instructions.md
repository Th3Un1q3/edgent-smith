# State machine

These rules bind edits under `state-machine/` and `state-machine.ts`. A change that breaks one is a defect even when the unit suite stays green. Add a state, guard, action, config key or mapping layer only after checking whether the library primitive already carries it; when it does, delete the old mechanism instead.

1. **Read identity at admission; never assume it.** An agent-name literal or a remembered parent id loops a subagent the host would have refused. `session_agent` in `machines/session/definitions.ts` destructures `agent` and `parentID` from `identityOf(context, event)` and requires `parameters.in.includes(agent)` with an empty parent; the `admission` arms in `machines/session/machine.json` pass `{ "in": ["rug"] }` to `#session.towards_goal` and an unguarded arm to `#session.free_work`.
2. **Parameterize one guard instead of adding an arm per value.** Each arm repeats its target, actions and tests, so a new value must be wired into every copy. `session_agent` takes `{ in: [...] }`, `field_present` takes `{ field }`, and `counter_below` takes `{ key, limit }` in `machines/session/definitions.ts`; the two `admission` arms differ only in that parameter.
3. **Flatten a nested state value at the boundary: leaf for display, dotted path for storage.** A stored leaf cannot resolve past the first compound level, and a dotted path in display breaks a reader expecting one state name. `core/machine.ts` exposes `state()` as the leaf (`validate`) and `statePath()` as the dotted path (`towards_goal.validate`), and `core/signals.ts` renders a compound value as its dotted path.
4. **Restore from the actor's persisted snapshot; never rebuild a state from a path.** XState restores a compound machine from its own snapshot and cannot resolve an initial state from a dotted path, so a hand-built restore lands on the wrong leaf or none. `core/machine.ts` passes the stored object to `createActor(created, { snapshot: { ...restored, context } })`, `core/snapshot.ts` carries `PersistedSnapshot` verbatim and reads no context field by name, and `SNAPSHOT_TTL_MS` sets expiry. Keep a path for display and logs (`stateValuePath` in `core/signals.ts`), not for restore.
5. **Declare a signal once in the manifest and name it in one policy slot.** Deriving the enabled list per state from the transition arms plus a `stateId` drifts from the manifest, and nobody can say which signals a state offers. `machines/session/signals.manifest.json` carries `describe` and `schema`; each `update_signals_policy` entry in `machines/session/machine.json` lists its own `set_enabled_signals`, and `validateSignal` in `core/signals.ts` rejects a name the registry does not declare. Add the declaration and its transition arm in one change.
6. **Build a guard from the runtime primitives, not a homebrew predicate.** A hand-kept table drifts from restore, display and hot reload. `not_parked` is `runtime.not(runtime.stateIn('parked'))` in `machines/session/definitions.ts`, built from the `runtime` that `core/machine.ts` passes to `createGuards`, and declared by the root `system_interrupted` arm and `towards_goal`'s `system_idle` arm in `machines/session/machine.json`.
7. **Add a context field to `SNAPSHOT_FIELDS` or the snapshot drops it.** `boundSnapshot` copies only the declared fields, so an unlisted field returns `undefined` after a reload while the fake host keeps it in memory. `machines/session/context.ts` builds `SNAPSHOT_FIELDS` from its `COPIERS`, and `core/snapshot.ts` drops every other key.
8. **Add a guard to the `GuardType` union before `machine.json` names it.** `createGuards` is typed `Record<GuardType, unknown>`, so an arm without a union member fails typecheck instead of failing at runtime. `GuardType` and the `SessionAgentParameters` interface live in `machines/session/definitions.ts`; `machines/session/machine.json` names only the type and params.
9. **Delete the mechanism you replace in the same change; keep one mechanism per concern.** A superseded table, a duplicate arm or a constant nothing reads stays in the tree and the next reader treats it as live. Signals moved from a per-state table plus a `stateId` parameter to the one `set_enabled_signals` slot in `machines/session/machine.json`; `idleCount` in `machines/session/context.ts` is written by the reset arms in `machines/session/machine.json` and read by no guard. Delete it with the change. Before deleting what looks like a duplicate, check that no requirement names it: the `always` and `on.admit` pairs under `admission` in `machines/session/machine.json` carry the same guard and target, and `always` stays because the requirement names `always`.
10. **Prove a behaviour change in a live `rug` session; the unit suite is a guard, not the proof.** The suite runs against a fake host, so the suites in `.opencode/plugins/tests/state-machine/` stay green while a subagent receives its own loop prompt. Run `opencode run --standalone --agent rug` per `.opencode/instructions/live-verification.instructions.md`; when the `[state-machine]` lines do not show the behaviour under test, the probe proved nothing, so change the prompt and repeat it until they do, then quote them.
