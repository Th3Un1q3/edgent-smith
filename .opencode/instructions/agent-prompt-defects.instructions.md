# Agent Prompt Defects

Apply every row below to each statement you add, keep, or review in an agent prompt. The question column decides the verdict: a statement whose question has no answer, or is answered "nothing changes", is corrected before the edit lands. Whether a line is a rule at all is decided by `writing-instructions.instructions.md`, Measurable rules.

| # | Defect class | Question (what breaks if deleted?) | Defect example | Correction |
|---|---|---|---|---|
| 1 | Past-run claim | Which rule changes if this sentence is false, and which tool output lets a reader confirm it? | "The last child burned 30 calls and still passed." | Delete the anecdote. Keep the rule it illustrates, and state that rule where the prompt lacks it. |
| 2 | Duplicated rule | If I delete this copy, does any behaviour change, which file owns the rule, and can the reader open that file? | The resume rule appears in both the Objective and the loop step. | Keep the copy in the owning file and replace the other with a pointer per `writing-instructions.instructions.md`, Pointer pattern, only when the reader can open that owner; otherwise the rule is missing, not duplicated (row 12). When the copies disagree, run the sweep in `skill-editing.instructions.md`, Contradiction sweep. |
| 3 | Unreachable instruction | Which tool in this agent's tool list performs this action, and does its permission allow it? | An orchestrator with no shell is told to run the test suite itself. | Name the child that has the tool and dispatch it, or delete the step. The dead-name test for a tool the card omits lives in `skill-editing.instructions.md`, check 7, which runs only on `.opencode/agents/*.md` and `.agents/skills/**`; on `.github/agents/*.agent.md` and `.github/prompts/**/*.md`, which that check does not cover, apply this row's tool-list test. |
| 4 | Unsourced quantity | Where does this number come from, can the reader check it with its own tools, and which branch reads it? | "A scouting pass costs about 12 calls." | Cite a source only where the reader can use one: the tool default, the schema, or a measured run it can re-run. Where the reader cannot use it, keep the number and delete the citation, placing it per row 8. A number that changes no branch is deleted and its branch kept. |
| 5 | Uncheckable adjective | What count, threshold, or observable decides this word? | "Relaunch when the attempt was substantially off." | Replace the word with the observable that decides it; the replacement passes the test in `writing-instructions.instructions.md`, Measurable rules. |
| 6 | Premise written as universal | On a first turn with no prior output, what does this rule tell the agent to do? | "Re-read its report before choosing the next step." | State the condition in the rule, or move the rule into the branch that creates the premise. |
| 7 | Unconsumed template field | Which rule, tool call, or check reads this field, and what breaks if I delete it? | The return template requires `Confidence:` and nothing reads it. | Add the rule or check that consumes the field, or delete it from the template and from every example that copies the template. |
| 8 | Inert provenance | Which decision changes if this citation goes, and can the reader open what it names? | "`description` cuts at 80 chars (`MAX_DESCRIPTION_CHARS` in `.opencode/plugins/helpers/workflow-types.ts`)." | Delete the citation and keep the number; the proof changes no call, so it belongs where the reader is not: a code comment at the definition, the commit message, or the reviewer's ledger. The ban on provenance in instruction text is `writing-instructions.instructions.md`, What it is not — Not a record. |
| 9 | Unfollowable pointer | Can the reader reach the target with its own toolset, and what rule is left if it cannot? | An orchestrator with no file read is told "the cap lives in `workflow-types.ts`". | Restate the rule in the prompt and point only at what the reader can open; drop the path. Pointer form: `writing-instructions.instructions.md`, Pointer pattern. Row 3 tests the action's tool, this row tests the pointer's target. |
| 10 | Maintainer fact | Does this line change the agent's next call, or only a reviewer's judgement of the rule? | "The cap is enforced by `truncateDescription` at the dispatch boundary." | Move it to the commit message or the reviewer's ledger, and keep in the prompt only the action it justifies, with its number and branch. |
| 11 | Authority disclaimer | Which number or branch changes when this hedge is removed? | "Roughly 80 characters, subject to change." | Delete the hedge and state the number. If the value is genuinely unset, name the observable that settles it or the branch at the boundary; unmeasurable qualifiers are the form `writing-instructions.instructions.md`, Measurable rules, already rejects. |
| 12 | Phantom duplicate | Can the reader open the owner, and does the rule survive deleting this copy? | A subtask prompt drops the resume rule because "`rug.md` owns it", and that prompt's reader cannot open `rug.md`. | A duplicated rule is a duplicate only when the reader can reach both copies. A rule that exists only in a file the reader cannot open is missing: state it here in full. Row 2's pointer applies once the owner is reachable. |

A cut statement takes its examples and cross-references with it, so the prompt has no line pointing at text that no longer exists.
