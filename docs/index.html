Overview

A Python 3.13 agentic system built on pydantic-ai — it turns issues into evaluated experiments.

"An issue-driven experiment loop with DevContainer-first development, orchestrated by a multi-agent architecture."

  • Runtime edge agents on pydantic-ai
  • OpenCode subagents & GitHub Copilot custom agents
  • Issue → experiment → evaluation, end to end
edgent-smith is not just a CLI: it is a multi-agent system where runtime edge agents execute experiments, OpenCode subagents and Copilot custom agents support development, and every idea flows through an issue-driven loop that ends in evaluation.

Evaluator


def load_dataset(set_spec: str):
    """Resolve "smoke" or "module:attr" to a dataset."""
    if not set_spec or set_spec == "smoke":
        return smoke_dataset

    if ":" in set_spec:
        module, attr = set_spec.split(":", 1)
        return getattr(importlib.import_module(module), attr)

report = run_eval(build_edge_agent(), load_dataset("smoke"))

Conventions

  • Python 3.13 with modern type annotations — from __future__ import annotations
  • Click: routing in cli/main.py, logic in commands/, services in cli/services/
  • just is the task runner for all primary workflows
  • DevContainers for consistent execution across local and CI

"Prefer uv run or just — no manual venv activation."

Anti-Patterns

"No src/ layout — root-level packages simplify import resolution in edge runtimes."

  • No manual venv activation — use uv run or just
  • Do not duplicate command logic — shared setup belongs in cli/services/
  • No generic instructions in project files

Workflows & Experiments

sequenceDiagram
    participant I as Issue / Idea
    participant E as Edge Agent
    participant T as Tools (CLI)
    participant X as Experiments State
    participant V as Evals
    I->>E: Experiment idea
    E->>T: Run experiment
    T->>X: Write state files
    E->>V: Evaluate result
    V-->>E: Baseline comparison
    E-->>I: Outcome recorded
Every idea enters the loop; every outcome is recorded against a baseline.
The loop is issue-driven: ideas arrive as issues, the edge agent runs them through the CLI, state lands in experiments/, and evals compare against baselines before the outcome is recorded back to the issue.
